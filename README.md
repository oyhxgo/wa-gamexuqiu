# 挖游戏需求 · wa-game-xuqiu

游戏设计需求挖掘「数字员工」Skill。把模糊的游戏想法、试玩记录、玩家抱怨、零散反馈和游戏数据，整理成**可验证、可排序、可交给游戏设计**的真实设计需求。

> 工作哲学：玩家提出的是方案（想要某个角色/功能），反复出现的卡关、流失和"玩腻"才更接近真实需求。

## 何时用

游戏想法很模糊 / 需要综测试玩反馈或玩家抱怨 / 玩法或关卡设计要根因 / 写游戏设计文档或做关卡前，需要玩家画像、核心玩法时刻、痛点（卡关/流失/玩腻）、设计优先级和试玩验证问题。

## 怎么用

- 输入至少两样：① 游戏想法或要解决的体验问题 / 原始材料；② 目标玩家是谁。已知平台（手机/PC/微信小游戏）、玩法类型、约束（包体/性能/商业化）也一并给出；或直接说「用演示场景」。
- 输出一份 **11 段《游戏设计需求报告》**：输入证据表 → 体验问题一句话 → 目标玩家角色 → 核心玩法时刻 → 设计层次拆解 → 游戏性根因（难度/节奏/反馈/信息/内容量/操作/技术）→ 设计机会清单 → 优先级(P0/P1/P2) → 可验证设计假设 → 试玩验证清单 → 阶段交接包。

## 文件

- `SKILL.md` — Skill 正文（WorkBuddy / Claude Skill 格式）。
- `agents/openai.yaml` — OpenAI Agent 接口定义，可作为独立数字员工部署。

## 配套

- 落地实现调用 `minigame-dev`（移动端纯净 UI、Boss 头顶血条、防晕手感、数据驱动阶段机、本地跑 + 无头验证 + 手机截图交付）。

## 原则

不虚构试玩/数据/玩家原话；数据与反馈冲突时保留冲突并给验证方案；平台约束必进交接包；优先级不能全 P0。
